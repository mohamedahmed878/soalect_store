# SOALECT

ماركة ملابس ستريت وير — هوية بصرية داكنة (Ink/Charcoal) مع لون أخضر ليموني (Lime)،
وعنصر بصري متكرر هو "تاج الملابس" (Swing Tag). فيه وضع ليلي/نهاري كامل.

## الحالة الحالية

✅ **backend/** — API حقيقي: Node/Express + MongoDB + JWT auth + Socket.io للمزامنة الحية + تسجيل دخول جوجل + رفع صور حقيقي + حماية (Rate limiting, Helmet, تعقيم المدخلات).
✅ **frontend/** — متصل بالكامل بالباك إند الحقيقي. تسجيل دخول بالإيميل أو بجوجل، برنامج تسويق بعمولة كامل، تصميم متجاوب للموبايل.
✅ **admin/** — لوحة تحكم متصلة بالكامل بالباك إند، تحليلات أرباح بفلترة زمنية، رفع صور من الجهاز، إدارة المسوقين.

## الترتيب الصحيح للتشغيل

لازم الباك إند يشتغل الأول، بعدين الفرونت إند والأدمن (في نوافذ PowerShell منفصلة).

### 1. الباك إند (اتبع التفاصيل الكاملة في backend/README.md)

```bash
cd backend
cp .env.example .env      # عدّل القيم جواه (Mongo URI, JWT secret, بيانات الأدمن)
npm install
npm run seed:products     # مرة واحدة بس
npm run seed:admin        # مرة واحدة بس — يعمل حساب الأدمن
npm run dev
```

هيشتغل على http://localhost:5000

### 2. الفرونت إند (متجر العميل) — في نافذة تانية

```bash
cd frontend
cp .env.example .env
npm install
npm run dev
```

هيفتح على http://localhost:5173

### 3. الأدمن (لوحة التحكم) — في نافذة تالتة

```bash
cd admin
cp .env.example .env
npm install
npm run dev
```

هيفتح على http://localhost:5174 — سجّل دخول بنفس بيانات `ADMIN_EMAIL` /
`ADMIN_PASSWORD` اللي حطيتهم في `backend/.env`.

## تسجيل الدخول بجوجل (اختياري)

عشان زرار "تسجيل الدخول بجوجل" يظهر ويشتغل:

1. روح [Google Cloud Console](https://console.cloud.google.com/) → APIs & Services → Credentials
2. اعمل "OAuth 2.0 Client ID" من نوع "Web application"
3. تحت "Authorized JavaScript origins" ضيف: `http://localhost:5173`
4. خد الـ Client ID وحطه في **3 مكان**:
   - `backend/.env` → `GOOGLE_CLIENT_ID=...`
   - `frontend/.env` → `VITE_GOOGLE_CLIENT_ID=...` (نفس القيمة بالظبط)
   - `admin/.env` → `VITE_GOOGLE_CLIENT_ID=...` (نفس القيمة برضو)
5. شغّل التلاتة تاني

لو سيبت القيم فاضية، الموقع هيشتغل عادي بس زرار جوجل مش هيظهر —
تسجيل الدخول بالإيميل وكلمة المرور هيفضل شغال زي ما هو.

⚠️ زرار جوجل في **لوحة التحكم** مختلف عن اللي في المتجر: بيرفض أي حساب
مش عنده صلاحية أدمن بالفعل، ومش بيعمل حساب جديد أبدًا — استخدمه بس مع
إيميل عملته أدمن قبل كده بـ `npm run seed:admin` أو ترقية يدوية.

## برنامج التسويق بعمولة

- أي عميل مسجل دخول يقدر يقدّم طلب انضمام من صفحة `/affiliate` (رقم طلب + بياناته)
- الأدمن يقبل أو يرفض الطلب من صفحة "المسوقين" في لوحة التحكم، ودوس على أي
  مسوق يفتحلك بياناته كاملة (بروفايل، طلباته، عمولته)
- الأدمن يقدر يحط **كود مخصص وسهل** لكل مسوق بدل الكود العشوائي، وكمان
  **يحدد قيمة خصم (ج.م)** الكود ده بيدّيها للعميل تلقائيًا عند استخدامه
- الكود ده شغال بطريقتين: رابط إحالة (`/products?ref=CODE`) أو كود يتكتب
  يدويًا في خانة "كود خصم" في السلة أو في صفحة الدفع — والاتنين بيتحقق منهم
  فعليًا مع الباك إند، وبيطبقوا نفس الخصم على الإجمالي
- **العمولة = نفس قيمة الخصم بالظبط.** لما العميل يستخدم كود المسوق ويتخصم
  عليه مبلغ معيّن، نفس المبلغ ده بالظبط بيروح عمولة للمسوق — من غير أي نسبة
  مئوية أو حسابات تانية. يعني لو حطيت خصم 50 ج.م للكود، المسوق ياخد 50 ج.م
  عمولة على كل طلب حقيقي بيه
- **العمولة بتتأكد بس لما الطلب يوصل "تم التسليم"** — أي طلب لسه في الطريق
  بيظهر كـ "عمولة معلقة" منفصلة لحد ما يتأكد التسليم

## إلغاء وحذف الطلبات

- **العميل** يقدر يلغي طلبه بنفسه من صفحة "حسابي" — بس وهو لسه في حالة
  "طلب جديد" (قبل ما الإدارة تأكده). بعد التأكيد، الإلغاء مش متاح للعميل.
- **الأدمن** يقدر يحذف أي طلب نهائيًا من قاعدة البيانات من صفحة الطلبات —
  الحذف فوري وبيتزامن لايف مع أي شاشة أدمن تانية مفتوحة.

## الصفحة الرئيسية والصورة (Hero)

الصفحة الرئيسية دلوقتي بتصميم ثابت (تصميم "Essentials Set" — العنوان،
التاجلاين، الأيقونات الأربعة، الأزرار كلها ثابتة في الكود). الحاجة الوحيدة
القابلة للتغيير هي **صورة المنتج الأساسي** على الجنب — من صفحة "الإعدادات"
في لوحة التحكم، ارفع صورة من جهازك وهتظهر على طول في الموقع. مفيش حاجة
تانية محتاجة تتغير كل فترة غير الصورة دي.

فيه كمان شريط إحصائيات (عدد العملاء، عدد المنتجات، المحافظات، مدة
الاسترجاع) بأرقام بتتعد لايف لما تدخل في مجال الشاشة، وقسم قصة البراند
بخلفية توقيع SOALECT شفاف في الخلفية.

## الأنميشن

الموقع كله فيه انتقالات وحركات ناعمة عن طريق `framer-motion`:
- **انتقال بين الصفحات**: كل صفحة بتدخل وتخرج بحركة fade/slide ناعمة
  بدل ما تتغير فجأة (`frontend/src/App.jsx`)
- **كروت المنتجات والفئات**: بترتفع بحركة سبرينج لما تعمل Hover عليها،
  مع ظل وglow خفيف
- **الأزرار**: بترتفع شوية عند الـ Hover وتنكمش عند الضغط
- **كود الخصم**: بيتفعّل بأنميشن ناعم (علامة صح خضراء) بدل ما يظهر فجأة
- **السلة الجانبية، إضافة للسلة، ظهور العناصر عند السكرول** — زي ما كانت من الأول

## الأمان

- JWT auth بتوكن صالح 30 يوم
- كلمة المرور: 8 حروف على الأقل، حرف ورقم (على الفرونت والباك إند)
- Rate limiting على مسارات تسجيل الدخول لمنع محاولات التخمين المتكررة
- Helmet (HTTP security headers) + تعقيم المدخلات ضد NoSQL injection
- كلمات المرور متشفرة بـ bcrypt، ومفيش رجوع للباسورد في أي response

## تسجيل الدخول مطلوب لإتمام الطلب

مفيش حد يقدر يعمل Checkout من غير ما يكون مسجل دخول — لو حاول، هيتوجه لصفحة
تسجيل الدخول/إنشاء حساب، وسلته هتفضل محفوظة لحد ما يرجع.

## المزامنة الحية

- **العميل يعمل طلب** → يظهر فورًا في صفحة الطلبات وفي نظرة عامة بلوحة التحكم، من غير Refresh.
- **الأدمن يغيّر حالة الطلب** (مثلاً لـ "تم التسليم") → يتحدث فورًا في صفحة "حسابي" بتاعة العميل، من غير ما يعمل Refresh.

كل ده شغال عن طريق Socket.io (`backend/utils/socket.js`).

## SEO (تهيئة محركات البحث)

- عنوان ووصف مختلفين لكل صفحة (Meta title/description) بيتغيروا تلقائي
  عن طريق `frontend/src/components/SEO/SEO.jsx`
- Open Graph + Twitter Card tags لمعاينة أحلى لما الرابط يتشارك
- Structured Data (JSON-LD) لكل منتج — بيساعد جوجل يفهم السعر والتوفر
  ويعرضهم في نتائج البحث (`frontend/src/components/SEO/JsonLd.jsx`)
- صفحات زي السلة وتسجيل الدخول وحسابي متعلّمة `noindex` عشان محركات
  البحث ماتضيعش وقتها فيها (مالهاش قيمة بحثية للزوار الجدد)
- `robots.txt` و `sitemap.xml` جاهزين في `frontend/public/`
- **Sitemap ديناميكي** كمان متاح على الباك إند (`GET /sitemap.xml`) وبيشمل
  كل صفحات المنتجات الحقيقية تلقائيًا وبيتحدث لوحده. لو عايز تستخدمه بدل
  الملف الثابت، لازم السيرفر (Reverse Proxy زي Nginx) يوجّه طلب
  `/sitemap.xml` للباك إند بدل ما يسيبه للملف الثابت في الفرونت إند —
  التفاصيل في `backend/routes/sitemapRoutes.js`

⚠️ **مهم قبل ما تنشر الموقع:** غيّر `https://www.soalect.com` في الأماكن
دي لدومينك الحقيقي:
- `frontend/index.html` (canonical + OG tags)
- `frontend/public/robots.txt` و `frontend/public/sitemap.xml`
- `backend/.env` → `SITE_URL`

⚠️ ملاحظة صادقة: الموقع شغال كـ SPA (React عادي من غير Server-Side
Rendering)، فالـ meta tags دي بتتحدث بعد ما الصفحة تحمّل. جوجل بيقرأها
عادي لأنه بيشغّل الجافاسكريبت، لكن لو عايز أفضل ظهور ممكن في معاينات
السوشيال ميديا (فيسبوك/واتساب) لصفحات منتجات معينة، الخطوة الجاية
المثالية هي إضافة SSR أو Prerendering — ده تحسين مستقبلي مش موجود دلوقتي.

## صفحات المتجر (frontend)

- الرئيسية (`/`)
- المنتجات (`/products`) — فلترة حسب الفئة + ترتيب
- تفاصيل المنتج (`/products/:slug`) — اختيار لون/مقاس/كمية
- سلة المشتريات (`/cart`) — وكمان Drawer جانبي بيظهر لما تضيف أول منتج
- إتمام الطلب (`/checkout`) — يتطلب تسجيل دخول + فورم حقيقي + كود خصم اختياري + تأكيد طلب برقم أوردر
- تسجيل الدخول (`/login`) و إنشاء حساب (`/register`) — بالإيميل أو بجوجل
- حسابي (`/account`) — بيانات + طلبات سابقة بحالة الطلب (تتحدث لايف) + إلغاء الطلب قبل التأكيد
- من نحن (`/about`)
- الاستبدال والاسترجاع (`/return-exchange`)
- تسويق بعمولة (`/affiliate`) — تقديم طلب انضمام ومتابعة الأرباح

## صفحات الأدمن (admin)

- الرئيسية (`/`) — إحصائيات + تحليل أرباح بفلترة زمنية (ساعة/يوم/أسبوع/شهر/سنة/الكل) + أحدث الطلبات
- المنتجات (`/products`) — إضافة/تعديل/حذف، سعر، مخزون، ألوان، مقاسات، رفع صور حقيقي من الجهاز
- الطلبات (`/orders`) — تغيير الحالة: New → Confirmed → Shipped → Delivered (يتحدث لايف عند العميل)، وحذف الطلب نهائيًا
- العملاء (`/users`) — قائمة كل العملاء المسجلين فعليًا في قاعدة البيانات
- المسوقين (`/marketers`) — قبول/رفض طلبات التسويق بعمولة، تحديد كود مخصص وقيمة خصم، ومتابعة أداء كل مسوق بالتفصيل
- التقارير والتحليلات (`/reports`) — رسوم بيانية للمبيعات والطلبات، مبيعات حسب الفئة/المحافظة/طريقة الدفع، الأكثر مبيعًا، عملاء جدد مقابل عائدين — كل ده بفلترة زمنية وبيانات حقيقية من قاعدة البيانات
- الإعدادات (`/settings`) — رفع صورة المنتج الأساسي في الصفحة الرئيسية فقط

## المنتجات التجريبية

6 منتجات جاهزة للتجربة، بتتحط في قاعدة البيانات بأمر `npm run seed:products`
(المصدر: `backend/utils/seedProducts.js`): تيشيرت أوفرسايز، هودي، تيشيرت
أبيض مينيمال، بنطلون كارجو، كاب، جوجر — كل واحد بألوان ومقاسات مختلفة عشان
تقدر تجرب الفلو كامل من التصفح للـ Checkout.

## تصميم متجاوب

كل الصفحات (المتجر ولوحة التحكم) شغالة على الموبايل: الناف بار بيتحول لقائمة
همبرجر، الجداول بتتلف أفقيًا لو المساحة صغيرة، النماذج والكروت بتتظبط
تلقائيًا على الشاشات الصغيرة.

## المتبقي / تحسينات مستقبلية

- صفحة "نسيت كلمة المرور"
- Refresh token / انتهاء صلاحية الجلسة تلقائيًا
- Pagination للمنتجات والطلبات لما العدد يكبر
- سحب أرباح المسوقين (payout) — دلوقتي العمولة بتتحسب وبس، السحب هيبقى يدوي
